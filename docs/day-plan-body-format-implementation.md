# 日计划专用文件：九格共用正文起笔格式

本说明供下一位开发者直接实施。年度日计划的标题归属和多窗格保存约定见[使用场景与数据规则](design-guide.md)。普通九宫格继续按[九宫格书写预设实施说明](cell-format-implementation.md)实现。两份说明涉及日计划时，以本文为准。

## 1. 用户应该看到什么

在「当前文件日计划设置」→「格子书写预设」里保留文件级开关。开启后只出现一个下拉框「默认正文形式」，三个选项为「普通段落」「无序列表」「有序列表」，初次启用默认选中「无序列表」。说明文字可用「当天的九个格子共用此格式。打开正文为空的格子时生效。」

每天的中心格由日计划生成日期标题，周边八格的标题由每日模板提供。因此本区移除第 1 层、第 2 层、H1–H6、关闭标题、层级加号等控件。模板某个位置留空时，编辑该格可直接写正文。「日计划显示与每日模板」仍是调整日期格式和模板标题的入口。命令面板和视图选项继续打开同一个文件设置窗口。

举例：当天中心格已有 `## 2026-11-23 周一`，周边格已有 `### 阅读`。选择「有序列表」并保存后，分别打开这两个格子，都在各自标题下面以 `1. ` 起笔，光标位于空格之后。以前创建、只有标题的格子也适用。如果「阅读」下已经写了「读完第一章」，打开时直接续写原稿。

「保存」提交本页设置，「取消」丢弃本次选择。已有记录的批量处理沿用独立按钮和确认流程，见第 5 节。关闭文件级开关后收起正文下拉框，恢复原有日计划编辑行为。

## 2. 配置、识别与兼容

**实现约定。** 继续用当前文件的顶层 `mandala_cell_format` 表达书写预设，给日计划增加一个标量 `dayPlanBody`。这样保存正文偏好只需改书写预设键，日期格式、年份和八格模板仍由 `mandala_day_plan` 管理。下例是已有日计划文件的 YAML 摘录：

```yaml
mandala_cell_format:
  enabled: true
  dayPlanBody: ordered-list
```

| 界面选择 | YAML 值 | 正文草稿及光标 |
| --- | --- | --- |
| 普通段落 | `paragraph` | 空白正文行，光标在行首 |
| 无序列表 | `unordered-list` | `- ` 后开始输入 |
| 有序列表 | `ordered-list` | `1. ` 后开始输入 |

- **识别文件。** 设置页和编辑器都从目标源文件有效的日计划配置识别文件类型，复用 `readDayPlanConfiguration` 及其旧键兼容逻辑。周视图、当天九宫格和侧栏打开同一个 section，应得到同样的规则。有效配置暂时关闭日计划时，面板仍属日计划专用，保留偏好，暂停日计划起笔。日计划 YAML 损坏时沿用错误提示，避免退回普通模式给日期格插入通用标题。
- **既有文件。** 缺少预设或 `enabled: false` 时默认关闭。打开面板或保存无关选项都不增加预设。已有有效且启用的旧分层预设时，优先读显式 `dayPlanBody`；旧文件缺此字段则沿用旧第 2 层的有效正文类型，缺省用无序列表。选择第 2 层是兼容决策：原实现只有周边格可能实际用到分层起笔。此值现在给九格共用。显式非法值应提示修正，编辑器回到原有起笔行为，不能静默把非法值当成用户选择。
- **写回时机。** 读取旧配置只在内存中解释。用户明确保存正文选择时写入新字段，旧 `levels`、`deeper` 和无关属性保留，日计划解析器只使用正文选项。用户明确关闭并保存时沿用既有文件开关语义，移除书写预设键。取消或仅保存其他选项时不迁移。普通文件继续读取自己的分层配置。
- **新建文件。** 保留现有全局「为新建文件启用格子书写预设」开关。关闭时新日计划不写预设；开启时写入日计划专用的启用状态和一种正文形式。建议沿用全局第 2 层的正文默认值（内置为无序列表），忽略各层标题设置，与旧文件折算一致。只在实际创建新日计划时复制一次。普通新建路径仍复制分层格式。

## 3. 打开格子与保存草稿

1. 先让现有日计划流程准备日期和八格标题。随后取得目标 section 的真实内容和编号。按年度日期序号识别每日中心格，按“日期序号.1”到“日期序号.8”识别当天八格。查不到内容、编号超出日计划范围或文件配置无效时，沿用现有编辑行为。不能把尚未加载的内容当成空串。
2. 识别归日计划管理的首行。中心格复用日期标题解析，并核对该 section 对应的日期。周边格用该位置的有效模板标题和现有模板标题生成函数比对。标题下仅有空白即视为正文空。历史日期可能保留旧模板标题；若现有数据无法确认来源，保守地保留原稿，禁止用今天的模板覆盖或凭任意 Markdown 标题推断。模板位置为空且格子全空时，从首行起笔。
3. 对符合条件的正文创建本次会话草稿。标题原文、缩进和已有换行以原文为准。复用已有可输入的空行，有标题且缺少正文行才追加换行。三种格式的前缀只落在正文行。正文已有非空内容时，包括任务、注释和用户自己留下的列表符号，保留原有编辑和光标逻辑。
4. 原文、准备好的草稿、光标以及本次生成的前缀必须属于同一次编辑会话。取消、切格、关窗，或未输入就保存，应得到逐字相同的原文，包括原有尾随空行。实际填写后只提交当前 section；用户主动换成另一种列表或段落，保存其输入。清理仅处理本次生成且未填写的占位。桌面恢复光标和移动端临时文件、空行锚点、显式提交都应遵守同一规则。
5. 标题留空要覆盖创建路径。目前年度生成逻辑在初始化部分周边格时会把空字符串传给 `upsertSlotHeading`，可能产出仅有井号的行。检查建档和后续补模板两个入口，空槽位保留空内容。旧文件已有含义不明的井号行，交由用户编辑，禁止通过打开文件批量清除。

## 4. 文件设置保存边界

[当前文件设置窗口](../src/obsidian/modals/current-file-mandala-settings-modal.ts) 目前会在保存启用中的日计划时调用日期标题刷新，即便用户只改了书写预设。实施时按实际修改的字段分开处理：

- 只改正文形式或开关，使用最新 frontmatter 合并写入书写预设字段。保留同一文件其他窗格刚保存的模板、日期设置和正文。
- 只有影响日期标题输出的配置发生变化，才在设置保存后调用已有日期刷新流程。显式刷新命令、修改每日模板、更新指定历史日期的标题继续使用各自入口。
- 仅修改正文偏好，不应引发对全年 section 的扫描、补日期或应用模板。保存成功后刷新当前文件设置缓存，下一次打开空正文采用新值，已经打开的草稿继续使用会话开始时的值。

## 5. 现有「统一格式」按钮

建议保留已有的显式批量功能，在日计划面板改名为「统一已有记录的正文格式…」。这一节是对现有按钮的适配方案，日常起笔不依赖用户执行它。

- 批量预览使用已保存的同一个正文形式，遍历有效日期中心格和当天八格。先按第 3 节分离可确认的标题与正文，只转换正文，然后拼回原始标题。模板留空的槽位可处理安全的纯正文。无法识别的标题、复杂正文、日计划范围外的 section 整格跳过。空正文保持原文。
- 现有普通格转换器将首行视作可提升或降级的标题，且计划器直接跳过日计划中心格。日计划需要单独的正文处理分支，复用安全段落／扁平列表转换逻辑，避免把日期或模板标题变成列表第一项。
- 继续显示待修改数和跳过数，保留确认、取消、零改动和一次原子写回。确认前重新校验文件、源 section 与相关配置，包含正文规则和用于识别标题的日期／模板数据。若目标格或规则变化则重新预览。重复执行应为零改动。关闭预设、配置无效或有未保存修改时，按钮不可执行。

## 7. 交付验收

| 操作或输入 | 通过标准 |
| --- | --- |
| 分别从命令和视图菜单打开日计划设置，再打开普通九宫格设置 | 日计划只有文件开关和一份正文选择；普通文件有原来的分层规则。只打开和取消均无写盘 |
| 旧日计划没有预设；另有旧文件已启用，第 1 层为段落、第 2 层为有序列表 | 前者默认关闭；后者九格均显示有序列表，读文件不触发迁移。改全局设置、重开已有文件后仍以文件为准 |
| 分别在日期中心格、已有模板标题的周边格、无标题的空槽位测试三种形式 | 验证这九种组合的草稿内容、光标及提交结果。仅有标题的旧日期也可起笔。日期、自定义日期显示和模板标题均保留原文 |
| 打开未输入后退出或提交；打开带正文、任务、用户标题、旧模板标题的格子 | 无输入时逐字保留原稿。对已有记录或归属不明的内容不插前缀，不误删原有 Markdown |
| 修改正文偏好，同时另一窗格修改模板或另一格记录 | 保存只修改目标键；无日期刷新。另一窗格之后打开空正文读到新规则，旧草稿不能覆盖并发修改 |
| 桌面切换日期、侧栏进入、周视图进入；移动端打开后取消与显式保存 | 同一目标 section 起笔一致，移动端文件中无多余空行锚点或列表占位 |
| 批量预览后取消、确认、再执行；预览后从另一窗格改目标格或模板 | 取消零写入；确认只转换安全正文，标题和复杂格原文保留；再执行零改动；冲突整批中止 |

在对应模块现有相邻的 Vitest 用例中补回归；重点断言原始 Markdown、光标位置、日期刷新调用次数和批量处理的目标 section。最后用临时日计划在 Obsidian 桌面与移动端核对空正文起笔、回车续项、取消及重开。代码交付按仓库 [AGENTS.md](../AGENTS.md) 执行。
